# Contributing

Thanks for looking. One thing about this repository changes what a contribution looks
like, so it comes first.

## This repository is published one way

The code is developed elsewhere and published here as one commit per release. Nothing is
pulled back from this repository. So:

- **A pull request opened here cannot be merged here:** the next release replaces the
  files and would run over it.
- **A commit pushed here disappears** at the next release.
- **Your change ships under the release commit,** with you credited in its notes, not
  as your own commit.

This is not a judgement about outside work. It keeps exactly one copy of the code.

## How to contribute

**Not yet.** The code is developed for our own use, and issues are closed for now. This
section says how contributions will work once they open.

- **A wrong reading:** give the filing's public URL, the page, what the output says and
  what is printed. Do not attach a PDF that is not public.
- **A patch:** put the diff in an issue, or open a pull request and say you are fine
  with it being applied upstream. It is applied there, credited, and ships in the next
  release.
- **A new profile or engine:** ask first. Every score here is measured on a set drawn at
  random and fixed before the test (see METHOD.md), so a change that cannot be measured
  that way is unlikely to be taken.

**Offering a patch grants ternlabs the right to use it** in this repository under the
Apache License 2.0, and in ternlabs' other versions of the code, paid ones included. You
keep your copyright, and the published version stays under Apache-2.0. Say so in the
issue if you do not agree, and the patch is not used.

## Test data

Sets hold public URLs, hashes and labels, never documents. Please keep it that way:
no PDFs, no page images, and nothing about a private person beyond what the filing
itself publishes.
